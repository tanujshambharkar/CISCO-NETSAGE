1. Executive Summary

Troubleshooting enterprise computer networks in lab and production environments requires rigorous correlation across all 7 layers of the OSI model. In complex topologies involving VLAN trunking, dynamic OSPF routing, DHCP relay agents, and stateful ACLs, students and junior network engineers frequently struggle with high cognitive overhead.

While Generative AI and LLMs have emerged as intuitive troubleshooting assistants, pure LLMs suffer from severe failure modes: hallucination of invisible artifacts, arithmetic errors in CIDR calculations, and proposals of destructive commands.

Cisco NetSage AI solves this through a novel dual-engine hybrid framework:

  • Deterministic Rule Engine (rule_checker.py): Static configuration validator executing 8 algorithms with zero hallucination.
  • Constrained AI Diagnostic Agent (diagnose_prompt.md): Structured LLM system prompt enforcing 7 safety guardrails, evidence-based reasoning, and strict JSON schemas.
  • Responsible AI Governance (responsible_ai_log.md): Empirical error tracking taxonomy with continuous feedback loops.

4. Deterministic Rule Checker (`rule_checker.py`)

The deterministic engine runs in standard Python without third-party dependencies, executing 8 key checks:

Check ID Severity Detection Mechanism
DUP-IP ERROR Tracks all assigned IP addresses; flags identical IPs assigned to distinct interfaces.
SUBNET-MISMATCH ERROR Detects conflicting subnet mask lengths assigned to interfaces on the same network.
MISSING-VLAN ERROR Finds VLANs referenced in access or trunk ports but missing from the switch database.
SHUTDOWN-INTF WARN Identifies interfaces left in an administratively shutdown state.
NO-GATEWAY INFO Audits host or switch configurations for missing default gateway or default routes.
TRUNK-NATIVE ERROR Compares native VLAN IDs across all trunk links to detect 802.1Q tag mismatches.
ACL-NO-PERMIT ERROR Flags ACLs with deny statements but no permit entries (resulting in total blackhole).
DHCP-POOL ERROR Calculates network boundaries and ensures default-router falls strictly within range.

5. Responsible AI Governance & Error Taxonomy

In accordance with AI safety best practices, all AI diagnoses are flagged with "human_approved": false until validated. Disagreements are logged to logs/responsible_ai_log.md:

Log ID Case Ref Error Type AI Misdiagnosis vs. Actual Root Cause Prompt Remediation Action
LOG-001 CASE-007 Misdiagnosis AI assumed interface down; actual cause was Gateway IP on foreign subnet. Instructed AI to calculate CIDR containment before interface checks.
LOG-002 CASE-011 Misdiagnosis AI claimed pool exhaustion; actual cause was router IP unexcluded. Added cross-reference rule between pool range and interface IPs.
LOG-003 CASE-018 Hallucinated Evidence AI hallucinated OSPF timer mismatch when timer output was omitted. Added negative few-shot example forbidding inference without evidence.
LOG-004 CASE-024 Incomplete Fix AI blamed routing for return drop; actual cause was ACL missing ICMP reply. Enforced explicit protocol enumeration for all active ACLs.
LOG-005 CASE-012 Wrong Layer AI jumped to Layer 7 DNS; actual cause was invalid Layer 3 default-router. Mandated bottom-up OSI ordering (Layer 1→2→3 before 7).

6. Cisco Packet Tracer Lab Topology & Configs

The complete Packet Tracer lab topology files are located in cisco_packet_tracer_lab/:

  • baseline_configs/: Clean, fully functioning Cisco IOS configs for R1 (Core/NAT/DHCP), R2 (Inter-VLAN Branch), SW1 (Core), SW2 (Access), and WLC 2504.
  • fault_scenarios/: Injection scripts for all 30 benchmark cases.
  • verify_lab.py: Automated validator testing all lab device configurations.
Testing in Cisco Packet Tracer:
Open Cisco Packet Tracer, paste the configuration from baseline_configs/, inject faults from fault_scenarios/, and run python src/rule_checker.py --config <file> to observe real-time diagnostics.
